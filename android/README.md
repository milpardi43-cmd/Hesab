# حسابیار (Hesabyar)

اپلیکیشن حسابداری و مدیریت مالی فروشگاهی برای کسب‌وکارهای کوچک ایرانی؛ ساخته‌شده با Kotlin و Jetpack Compose، کاملاً فارسی و راست‌به‌چپ، با تقویم هجری شمسی، واحد پول تومان و معماری Offline-First.

این مخزن، نسخه اندروید محصول است و یک استارتر SwiftUI برای ادامه مسیر iOS نیز در پوشه `ios/` قرار دارد. نسخه نمایشی مرورگر در یک پروژه جداگانه (پوشه `site/` در پروژه Webdev) نگهداری می‌شود.

## خروجی‌های آماده

| خروجی | مسیر | توضیح |
|---|---|---|
| APK امضاشده (Release) | `app/build/outputs/apk/release/app-release.apk` | قابل نصب روی اندروید ۷ و بالاتر |
| AAB امضاشده (Release) | `app/build/outputs/bundle/release/app-release.aab` | مناسب آپلود در کافه‌بازار / Google Play |

نسخه: `1.0.0` (versionCode = 1) · applicationId: `ir.hesabyar.app` · minSdk 24 · targetSdk 35.

## امکانات نسخه ۱٫۰

- **داشبورد مدیریتی**: موجودی کل حساب‌ها، فروش/دریافت/هزینه/سود امروز، طلب و بدهی، نمودار روند فروش، هشدار موجودی و یادآوری‌های نزدیک.
- **فروش**: فاکتور نقدی، نسیه و ترکیبی؛ انتخاب کالا، تعداد، تخفیف، طرف حساب و حساب دریافت؛ کسر خودکار موجودی و ثبت طلب مشتری؛ مرور و فیلتر فاکتورها و جزئیات سند.
- **برگشت از فروش**: بازگرداندن کالا با استفاده از موجودی و میانگین بهای تمام‌شده جاری، اصلاح حساب مشتری و انبار.
- **خرید**: فاکتور خرید با تأمین‌کننده، کرایه حمل، تخفیف و پرداخت نقدی/نسیه؛ افزایش موجودی و به‌روزرسانی میانگین بهای تمام‌شده؛ ثبت بدهی تأمین‌کننده.
- **هزینه‌ها**: ثبت هزینه با دسته‌بندی، حساب پرداخت و توضیح؛ کسر از حساب و نمایش در گزارش‌ها.
- **کالاها و انبار**: افزودن/ویرایش کالا، بارکد، قیمت خرید و فروش، حداقل موجودی، ارزش انبار و گردش ورودی/خروجی؛ اصلاح موجودی با سند حسابداری.
- **اشخاص**: مشتریان و تأمین‌کنندگان، مانده بدهکار/بستانکار، مانده اولیه، دریافت از مشتری و پرداخت به تأمین‌کننده، گردش حساب هر شخص.
- **حساب‌ها**: صندوق، بانک و کارتخوان؛ انتقال وجه بین حساب‌ها و اصلاح صندوق با ثبت اختلاف.
- **گزارش‌ها**: گزارش روزانه و ماهانه فروش، خرید، هزینه، سود ناخالص/خالص، پرفروش‌ترین کالاها و مانده اشخاص.
- **یادآوری‌ها**: سررسید بدهی‌ها، مطالبات و کارهای مالی؛ اعلان با WorkManager و علامت‌گذاری انجام‌شده.
- **تنظیمات و داده‌ها**: اطلاعات کسب‌وکار، ظاهر و اعداد فارسی، پشتیبان‌گیری JSON، خروجی CSV و Excel، بازیابی و بازنشانی؛ اشتراک (آماده اتصال به درگاه) و درباره برنامه.

## معماری

پروژه به‌صورت چندماژوله و لایه‌ای طراحی شده تا افزودن قابلیت‌های آینده بدون دست‌زدن به هسته حسابداری ممکن باشد:

```
:app        → Jetpack Compose UI، ViewModelها، ناوبری، WorkManager، Hilt
:data       → پیاده‌سازی Repositoryها، PostingExecutor، Backup/CSV/XLSX، Mapperها
:core       → Room (Entity/DAO/Database)، DataStore، Design System، نوتیفیکیشن، XlsxWriter
:domain     → مدل‌ها، AccountingEngine، JalaliDate، PersianText، UseCaseها و رابط Repositoryها (Kotlin خالص)
```

### جریان ثبت عملیات

1. UI یک Command (مثلاً `RecordSale`) می‌سازد.
2. `AccountingEngine` صحت داده و مانده‌ها را بررسی می‌کند و یک `PostingPlan` با ردیف‌های بدهکار/بستانکار، اثر روی موجودی و اثر روی طرف حساب تولید می‌کند.
3. `PostingExecutor` کل سند، ردیف‌ها، به‌روزرسانی موجودی/میانگین بهای تمام‌شده/مانده حساب‌ها و تراکنش را در **یک تراکنش اتمیک Room** ذخیره می‌کند.
4. در صورت خطا، هیچ بخشی از سند ثبت نمی‌شود؛ برای ابطال، سند معکوس (Reversal) ثبت می‌شود و سند اصلی حذف نمی‌شود.

### تصمیم‌های مهم

- **Offline-First**: دیتابیس محلی Room منبع حقیقت است؛ برنامه برای کار روزمره به اینترنت نیاز ندارد.
- **پول**: مبالغ به تومان و به‌صورت عدد صحیح ذخیره می‌شوند تا خطای گرد کردن اعشاری رخ ندهد.
- **تاریخ**: پیاده‌سازی مستقل تقویم جلالی در `:domain` با تست واحد، بدون وابستگی به کتابخانه خارجی.
- **قابل توسعه**: رابط Repositoryها در دامنه تعریف شده‌اند؛ تعویض Room با KMP/SQLDelight یا افزودن Sync آینده بدون تغییر UI ممکن است.

## ساخت و اجرا

پیش‌نیازها: JDK 21، Android SDK 35 و Build Tools 35.0.0. مسیر SDK در `local.properties` تنظیم می‌شود.

```bash
export ANDROID_HOME=$HOME/android-sdk
./gradlew :domain:test :data:testDebugUnitTest     # ۳۲ تست
./gradlew :app:assembleDebug                        # APK دیباگ
./gradlew :app:assembleRelease :app:bundleRelease   # APK و AAB امضاشده
```

نصب APK روی دستگاه متصل:

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

### امضا

برای حفاظت از مخزن عمومی، هیچ keystore یا رمز امضایی در این مخزن نیست. برای خروجی Release امضاشده، یک keystore اختصاصی بسازید و مشخصاتش را در فایل محلی `keystore.properties` بنویسید؛ این فایل و keystore در `.gitignore` هستند. هیچ‌گاه کلید امضا را commit نکنید. گم‌شدن کلید، به‌روزرسانی همان اپ در فروشگاه را دشوار یا ناممکن می‌کند.

## iOS

پوشه `ios/` شامل یک استارتر SwiftUI با همان زبان بصری، مدل‌ها، فرمت‌های فارسی/جلالی، داده نمونه و صفحه‌های داشبورد، فروش، هزینه، تراکنش‌ها، کالاها، اشخاص و گزارش است. این بخش عمداً از هسته اندروید جدا نگه داشته شده تا مسیر مهاجرت به Kotlin Multiplatform یا پیاده‌سازی بومی Swift باز بماند. راهنمای کامل: `docs/IOS_GUIDE.md`.

## محدودیت‌های نسخه ۱٫۰

- تک‌کاربره و محلی است؛ همگام‌سازی ابری و چند دستگاه هنوز پیاده‌سازی نشده.
- اتصال به درگاه پرداخت/اشتراک فقط به‌صورت رابط آماده است و به سرویس واقعی متصل نیست.
- استارتر iOS در حد اسکلت نمایشی است و با Room/KMP به‌طور کامل به دامنه متصل نشده.
- APK و AAB با کلید نمونه امضا شده‌اند و برای انتشار عمومی باید کلید تولیدی جایگزین شود.

## نقشه راه پیشنهادی

1. تکمیل هم‌ارزی iOS با SwiftData یا KMP + SQLDelight.
2. همگام‌سازی ابری اختیاری با رمزنگاری end-to-end و حل تعارض.
3. پشتیبانی چند فروشگاه/چند کاربر و نقش‌ها.
4. اتصال به دستگاه بارکدخوان/پرینتر حرارتی و فاکتور PDF.
5. اشتراک واقعی از طریق کافه‌بازار/درگاه ایرانی و مدیریت لایسنس.
6. تست‌های UI با Compose Test و CI برای ساخت خودکار APK/AAB.
